# Changing an approved example

An approved test is the contract. When the build shows an example is wrong, take the new wording back through `examples` step 3, then update the ticket and the test together. In the `red-pen` draft, the section's location line names the example's test file (`tests/charm_approved_examples.test.sh:new`). The plugin's `approved-spec-guard` refuses an edit that changes, adds or removes a Given, When or Then comment line until the user changes its section and closes the draft, which opens that file alone for edits. An Edit or Write that keeps every one of those lines, such as a setup fix or a helper, goes through with no draft, and the file's tests and its mutation pass run again after it. A file approved before its examples were written into it has no such lines and stays locked whole: copy its approved examples from its ticket into it as Given, When and Then comments above their tests, and take that edit through red-pen once. The section holds `- [ ] approve` on the line under its location, so the user approves the wording as it stands by ticking it. A close that leaves the section unchanged, box unticked, opens nothing, even though `red-pen` takes it as approval: tell the user the test stays locked, and reopen that section.
