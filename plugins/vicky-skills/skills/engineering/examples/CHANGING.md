# Changing an approved example

An approved test is the contract. Retiring, merging or replacing an approved example is a change too, and a "Going with" pick never covers it. When the build shows an example is wrong, take the new wording back through `examples` step 3, then update the ticket and the test together. Open the draft page with your pick on it at once, with no question in chat first: the user refuses or rewrites it on the page. A chat message never retires or reverses an approved example, even when it states the new rule: record the change only once its page comes back ticked. In the `red-pen` draft, the section's location line names the example's test file (`tests/charm_approved_examples.test.sh:new`). An Edit or Write that keeps every Given, When and Then comment line of a file on main, such as a setup fix or a helper, needs no draft, and the file's tests and its mutation pass run again after it. A file approved before its examples were written into it has no such lines and stays locked whole: copy its approved examples from its ticket into it as Given, When and Then comments above their tests, and take that edit through red-pen once. The section holds `- [ ] approve` on the line under its location, so the user approves the wording as it stands by ticking it. A close that leaves the section unchanged, box unticked, opens nothing, even though `red-pen` takes it as approval: tell the user the test stays locked, and reopen that section.
