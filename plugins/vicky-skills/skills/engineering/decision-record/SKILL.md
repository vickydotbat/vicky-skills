# Decision record

> _What is written in the log was true on the day it was written, and stays true after._

A kept record is never edited, so it must be written to stay true whatever happens later. The format, the forces and the status lines are in [FORMAT.md](FORMAT.md). Read it before the first step.

The `adr-scope-hint` hook repeats the scope and the append-only rule when a record is edited. `docs/agents/domain.md` names the record folder and the format. When its `ADR format:` line names a repo template, write in that template and run step 5 with `--template`, which checks only the rules that hold in any shape. Every other value (`decision-record`, or the older `ADR-FORMAT.md` and `true-names`), or no line, means [FORMAT.md](FORMAT.md).

## Steps

1. **Test the scope.** State the rule in one sentence and name two later decisions it will govern. Check the three tests in FORMAT.md's Scope. When one fails, write the why as a comment at the code that builds it and stop. Done when the rule and its two governed decisions are written down, or the comment is.
2. **Find the records it touches.** List the record folder and read every record whose title or forces cover the same ground, and every record in another repo the agent file points at. A record it replaces in full, with nothing it states still true, gets retired in step 6. A record it replaces in part gets superseded there, and a record it adds to gets amended. Done when each touched record is named as retired, superseded, amended or untouched.
3. **Name the forces.** Write each outside limit the rule rests on as a dated, past-tense `- F<n>: ` line, with its source read this session (a measurement, a doc, a ticket comment). A preference or a plan is not a force. When the rule supersedes a record, one force says what changed in the old record's force. Done when every force has a date and a source you read.
4. **Write the record.** Number and name it as FORMAT.md's Shape says. Open the Decision with `While` and the forces it rests on. Give the Consequences, with the option turned down and each break the rule causes: a stored form, a public call or a file layout that changes, with its migration or the words `No migration:` and who that leaves behind. Name the Guard: the test, lint, CI step or hook that fails on drift. When the repo has none and one fits in this effort, build it now (the found-work rule). A real check's failure message or header comment names the record number, so a reader who trips it finds the why. Otherwise write `Review only.` Done when the file is on disk and a named check's text holds the record number.
5. **Check it.** Run `bash scripts/check-adr.sh <record>` from this skill's folder on the new record and on each record step 6 touches. With a repo template, run `bash scripts/check-adr.sh --template <record>` instead. Done when it exits 0.
6. **Retire or mark the old records.** Retire a record replaced in full, with nothing it states still true: the new record's Consequences hold `Retires ADR-NNNN: <why>.`, so a search for the number still finds the reason, and you delete the old record from the repo in the same commit. On a wiki, tombstone the old page instead: replace its body with one line that points at the new record. A record replaced in part stays and gains one appended Status line: `Superseded by ADR-NNNN on YYYY-MM-DD: F<n> no longer holds.` when its rule is replaced but a fact in it still holds, or `Amended by ADR-NNNN on YYYY-MM-DD.` when the new record adds to it. A kept older-shape record takes `Superseded by ADR-NNNN.` as its last line instead. Change nothing else in a kept record. Restate no record's rule in an agent file, README or doc: a copy drifts from the record. Point at the record by number instead ("Money rules: ADR-0002."). No hook backs this yet: telling a restatement from a pointer needs judgement. Then run `plot-twist` with the old rule, so tickets, docs and agent files stop citing it, unless `plot-twist` started this run. Done when each retired record is deleted (or its page tombstoned) and named by a Retires line that step 5's check passes, `git diff` on each kept record shows one added line and nothing removed, and every other file this effort touched names the rule only by record number.
