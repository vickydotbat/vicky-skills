# Never lupus

> _It's never lupus. It's whatever turns the loop red._

A bug is found by a **loop**: one command that goes red on this bug and green once it is fixed. With a loop, finding the cause is mechanical. Without one, reading code is guessing. Trace the bug in the code: "the build is stale" is a diagnosis too, and it needs proof such as an artifact hash or a logged version. A key refused by a forge gets the same proof: the `publickey-hint` hook names the checks.

Show commands and output with every secret replaced by `<REDACTED>`. Keep credentials in environment variables, out of the loop's text.

**Outside report.** When you are handed a bug report or review that someone else wrote, first run `bash ${CLAUDE_PLUGIN_ROOT}/skills/shipping/deathmatch/scripts/mark-outside.sh <session id> <what>`, then run `deathmatch` to check the report's claims. In that run, fix nothing, push nothing and post nothing.

## Steps

1. **Build the loop.** Try these in order and take the first that reaches the bug: a failing test at the seam the bug passes through, an HTTP call against a running server, a CLI run diffed against known-good output, a headless browser script, a captured request or log replayed through the code, a small harness around the failing path, a random-input loop, `git bisect run` between a good and a bad state, or the same input through two versions. When only a person can trigger it, copy [`scripts/ask-the-human.sh`](scripts/ask-the-human.sh) and drive them through it. Put a memory and time limit on anything that can run away. Done when you have run one command that drives the real code path, asserts the user's exact symptom, gives the same verdict every run (or a high, pinned rate for a flaky bug) and takes seconds. When no loop is possible, stop: list what you tried and ask the user for access, a captured artifact or permission to add logging. <!-- kept 2026-11-10: a headless browser loop and a replayed transcript each found a root cause first time -->
2. **Check the peripheral.** List the state the case depends on beyond the code: an item identified or not, a level, a mode, a setting, a stale build. Read each one, and ask the user in one line for any you cannot read yourself, such as how an item looks in their game. A bug claim names the state each case was seen under, and the agent calls nothing a bug until each state is read or the user answers. Done when every state on the list has a value, and a state still open is asked.
3. **Reproduce and shrink.** Run the loop and confirm it fails the way the user described, not some nearby way. Then cut inputs, callers, settings and steps one at a time, rerunning after each cut. Done when removing anything left makes the loop pass.
4. **Rank three to five causes**, each with the prediction it makes: "if X is the cause, changing Y makes the bug go away". Show the list to the user before you test it, since they may rule one in or out at a glance. Done when every cause has a prediction.
5. **Test one prediction at a time.** Use a debugger first, then logs at the boundary that tells two causes apart. Before you compare two timestamps, read each source's time zone: a container or server log often runs on UTC while the desktop runs local time. Tag every log line with one prefix, such as `[DEBUG-a4f2]`. For a slowdown, measure a baseline first and bisect against it. When the cause is a platform limit (a cap, quota or size the platform sets), the report gives the headroom under normal use (how much a typical session spends against the cap), and the limit goes to `engrave` unasked. Report it with the headline `🩺 It's not lupus. It's <the cause>.` Done when one cause is confirmed. When every ranked cause is refuted, go back to step 4 with what the tests showed.
6. **Sweep the siblings.** Step 3 narrowed the bug to one path, so widen out again before the fix. State the confirmed cause as a pattern, such as "a call reaches sink Y without check Z". List every other path to the same effect: other callers of the same sink, sibling modules, a second way to do the same task, copies of the block. Find them by the pattern's shape with grep or codegraph, not by name, since a copy is often renamed. Run the loop's check on each. Done when each path on the list reads red, green, or "n/a: <reason>", and the report adds "Siblings: <n red>, <n green>".
7. **Fix it test-first, at the source.** Pick the fix first: make illegal states unrepresentable, the first design move in [STANDARDS.md](../../STANDARDS.md). Find the input or offer that lets it exist (a menu row, a parameter, a call that should never be made) and remove it. A fix that only catches or reports the bad state downstream gives, in the commit or pull request, the reason the source can't be closed. Turn the shrunk loop into a failing test at a seam where the bug really happens, covering every red path from step 6. Watch each fail, fix, watch each pass, then rerun the original loop. When two ways to do one task need not both exist, offer to collapse them into one. When no seam can hold the bug, say so: that is a design finding. Done when the original loop passes, every path from step 6 is green or n/a, and the fix closes the source, or names why it can't.
8. **Clean up.** Remove every tagged log line (grep the prefix) and every throwaway harness. A comment the fix leaves follows [STANDARDS.md](../../STANDARDS.md)'s "Why-comments". Name the confirmed cause in the commit or pull request. Done when the grep finds nothing.
