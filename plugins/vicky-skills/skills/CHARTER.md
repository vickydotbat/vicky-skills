# Charter

What the whole workflow is for. Every skill names the lines it serves on its `Charter:` line, and a step that keeps a skill's letter while it breaks one of these lines is a snag. The `familiar` names the line each snag broke. A snag no line fits means the charter lacks a line: draft it for the user to approve.

- **C1** You get what you meant. The observer's behaviour is the spec, not the ask's letter.
- **C2** Done is proven by the agent, from the observer's side: both halves, the round trip, the look on screen.
- **C3** Facts come from their source, read this session.
- **C4** One of everything: one entry per need, one copy of logic, one pull request per effort, CI once.
- **C5** The user's attention is the scarcest thing. A cheap pick is taken, a proposal comes unasked, nothing is asked twice.
- **C6** Finish, don't file. Found work is done now, and the backlog shrinks.
- **C7** The user's machine, data and secrets stay safe, and nothing private leaves.
- **C8** It works in any repo.

A line changes only after the user approves its new text on a `red-pen` page. A code is never reused for a different line.
