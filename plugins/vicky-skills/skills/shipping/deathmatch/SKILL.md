# Deathmatch

> _Two branches enter. One branch leaves. Round one: fight!_

A **deathmatch** sends **opponents** at the diff between `HEAD` and a fixed point. Each opponent holds one angle, reads [STANDARDS.md](../../STANDARDS.md) and the repo's own rules, and tries to break the change. A **finding** counts only when it is **proven**: a command shows the failure and the failure breaks the intent, or the finding's own fix beats the branch in an arena contest. A finding that is neither is **unproven**: it is listed and never blocks.

The main thread does the TDD, red to green. Deathmatch is the refactor: its job is to kill the weaknesses the build left. It runs once per effort, inside `make-it-so` before the pull request goes ready (`verdict.sh due` says whether the head commit still needs one), and on outside text when `assimilate` or another skill hands it a report.

## Opponents

Each opponent is an agent, `vicky-skills:<angle>-opponent` (`intent-opponent`, `runaway-opponent`), that holds its angle and works to [OPPONENT.md](OPPONENT.md)'s contract. An opponent fights when the diff reaches its angle, as `scripts/triggers.sh <fixed-point> [body file]` prints it (`fight: <angle>` or `out of reach: <angle>`), and Security also when an outside report claims a security hole. The six core angles:

- **Intent**, always: the observer's view. Which prose ask has no approved example? The tests already prove each example passes.
- **Holds**, when a file other than Markdown changes: break each path the change reaches that no `sentinels` receipt covers. Can its tests fail?
- **Cause**, when a commit or the body claims a fix: symptom or cause, by [CAUSE.md](CAUSE.md). A symptom fix, or a suspected better way, opens the arena round.
- **Simplicity**, when a file other than Markdown changes: what can be deleted, merged or not built. Its proof is a deletion that leaves every check green.
- **Standards**, always: the repo's rules and STANDARDS.md, quoted by leading word.
- **Claims**, when the body has a Proof section: the pull request body's Proof and Status against what actually ran.

Triggered opponents fight when `scripts/triggers.sh <fixed-point>` names them, and Security also fights on each file an outside report claims a security hole in, whatever the diff triggers. Otherwise they stay out of reach: **Runaway** (the diff starts a process, loop, server or container) and **Security** (a route, permission check, user input, parser, query, rendered user content, secret, process spawn, network call or CI permission). Every opponent run goes through `scripts/cap.sh`, so a run over its time or memory cap is stopped and reported, and nothing else on the machine is touched.

Before any opponent fights, `scripts/prefight.sh <fixed-point>` runs the Leak check. A local path, host or secret in the diff stops the deathmatch with the file and line. The Host check is the sealed copy: an undeclared tool fails there by itself.

## Steps

1. **Pin the checkout, the fixed point and the spec.** Take the effort's worktree and its pull request's merge-base when `make-it-so`, `warp` or `assimilate` calls this skill, and never ask. Otherwise use what the user named, or ask. Find the spec: the ticket's approved examples, or the user's ask. Done when `git diff <fixed-point>...HEAD` has content and you hold a spec or "none".
2. **Gather the law.** Read the repo's `AGENTS.md`, its `docs/agents/` files and `${CLAUDE_PLUGIN_ROOT}/skills/STANDARDS.md`. When they name rules kept outside the repo, write them verbatim into one law file in scratch and use the path `test -s <file> && realpath <file>` prints. `review-brief-guard` refuses an opponent brief that names a missing file. Done when you hold the law file's printed path, or can say the repo keeps no rules outside it.
   Proven by: plugins/vicky-skills/evals/deathmatch/gate-own-diff
3. **Pre-fight.** Run `scripts/prefight.sh <fixed-point>`. Inside `make-it-so`, reuse the checks its step 1 ran on the same head. Called from anywhere else, run the repo's own tests and checks once. Make the sealed copy: a fresh clone in scratch, its own home folder, only the dev shell's tools on PATH. A repo too heavy to copy runs on the host, and its findings say "proven on host". Pin the effort's worktree with `scripts/sealed-check.sh snapshot <worktree> > <scratch>/worktree.snap`. Done when the Leak check passed, the snapshot is written, and you hold each failing check's failing lines, not its log.
4. **Fight.** Run `scripts/triggers.sh <fixed-point> <body file>` (no body file before a pull request exists), and `scripts/batch.sh <opponents>` for how many fight at once and each one's memory cap, counting every opponent but Holds. Skip it when Holds is the only one sent. Dispatch each opponent agent `triggers.sh` sent to fight, on the default model, at most that many at a time: when one reports, send the next. Holds fights alone, after the others, with the cap `scripts/batch.sh holds` prints: its mutation pass builds and tests at once. A run an opponent reports stopped at its memory cap is not run, never clean. Send that opponent once more, alone, with the `batch.sh holds` cap when that cap is larger than the one it stopped at. A stop with no larger cap to retry with, or a second stop, is the report's `Humiliation.`, naming each path left untested. Give each the memory cap for its `cap.sh` runs, Security the files an outside report claims a security hole in, and the sealed copy, the fixed point, the law file's path, the spec and the failing lines that bear on its angle. Each opponent returns findings, each with the command that proves it, or the patch that would fix it. After each report, before the next opponent goes, run `scripts/sealed-check.sh check <sealed copy> <pinned sha> <worktree> <scratch>/worktree.snap`. On the host, the worktree is the copy, and a failure there is restored by hand, never by `reset`. On exit 1, discard that opponent's findings, run `scripts/sealed-check.sh reset <sealed copy> <pinned sha>`, and send that opponent once more. A second exit 1 for it is the report's `Humiliation.`, naming the opponent. Done when every opponent sent to fight has reported on every file in its reach, and the check passed after each report it kept.
   Proven by: plugins/vicky-skills/evals/deathmatch/holds-capped-reruns
5. **Prove.** Run each finding's command again in the sealed copy, under `scripts/cap.sh`. Keep the finding when the output shows the failure and the failure breaks the intent. A finding with no command, such as a deletion or a rename, goes to the arena. When two opponents disagree on one finding, a second model judges that finding alone, and no undisputed finding reaches it. Done when each finding is proven, unproven, or waiting for the arena.
6. **Arena**, only when Cause ruled a symptom fix, an opponent suspects a better way, or a finding waits for a contest. Build a rival from the problem alone, as CAUSE.md's third question does, and each waiting finding's patch. Run every check on each candidate and on the branch. Score them on one rubric: does the bad state still happen, what it deletes, what it adds, what STANDARDS.md says. Graft each part where a rival wins onto the branch, and keep the rest of the branch. A finding whose patch wins is proven. A branch that fixes the cause, with no better way suspected, holds no arena. Done when each candidate has its score and each graft is named.
7. **Fix or report.** On the effort's own branch, fix each proven finding that waits on no one: its test red first, then green, never changing an approved test. On outside text (an outside pull request, bug report or review), run `scripts/mark-outside.sh <session id> <what you read>` as soon as you read it, then fix nothing, push nothing, file nothing and post nothing: return the findings, and a person or a later run acts on them (`outside-text-guard` holds this). Done when each proven finding is fixed with its test, or listed for its owner.
8. **Report** to `deathmatch.md` at the path the user names, else in scratch, and in the pull request's Proof as `Deathmatch verdict for <head sha>: <n> proven findings`. Name each opponent `triggers.sh` left out of reach, and state `no trigger in the diff` when it printed it. List proven findings with their command and output, then unproven ones under `Unproven, not blocking`, then each arena score and graft. Outside `make-it-so`, which adds the Laws line itself, add it from `bash ${CLAUDE_PLUGIN_ROOT}/skills/shipping/engrave/scripts/law-lint.sh prove <fixed-point>`. Give each fixed finding a prevention verdict: engrave it as the cheapest check, hook or STANDARDS.md line that holds it, or say why not. Open the chat report with the announcer's call: `Flawless victory.` for 0 proven findings, `First blood: <the finding>.` for one, `<n> proven. Finish them.` for more, and `Humiliation.` when an opponent's run stopped at its cap and step 4 left it no retry. Then run `cerebro` as a forecast. Done when the report holds every finding, the verdict line is in the pull request, and cerebro has proposed or found nothing.

Proven by: plugins/vicky-skills/evals/deathmatch
